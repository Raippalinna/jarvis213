# Tvärvetenskap som prövbara deluppgifter

Använd ett fält endast om det kan ändra svaret, minska osäkerheten eller upptäcka ett viktigt fel.
En ämnesetikett är inte expertbevis. Utse den som bäst kan testa hypotesen, inte flest specialister.

| Lins | När den behövs | Leverans som kan kontrolleras | Undvik |
|---|---|---|---|
| Matematik och statistik | Mängder, risk, optimering, prognos, påstådd förbättring | Definitioner, enheter, beräkning/kod, basfrekvens, intervall och känslighetsanalys | Påhittade sannolikheter, precision utan data |
| Fysik och systemteknik | Material, energi, konstruktion, kapacitet, flaskhals | Randvillkor, enhetskontroll, bevarandelag där tillämplig och verifierbar modell | Att låta en metafor bli fysisk mekanism; konstruktionsbeslut utan rätt kompetens |
| Kvantfysik | Verkligt kvanttekniskt problem med relevant data | Vilket kvantproblem, vilken hårdvara/algoritm, klassisk jämförelse och mätbart utfall | Att kalla LLM-idéer eller parallella agenter kvantberäkning |
| Psykologi och beteende | Kundval, förhandling, team, användarflöde | Beteendehypotes, alternativa förklaringar och etiskt experiment | Diagnoser, dold manipulation, universella slutsatser från ett litet försök |
| Historia | Strategisk analogi, organisationsutveckling, återkommande kris | Minst ett jämförelsefall och ett motfall; skillnader i mekanism och kontext | Att likhet i berättelsen blir bevis för samma utfall |
| Filosofi och beslutsteori | Motstridiga mål, osäkerhet, etik, begrepp | Explicit mål, antaganden, starkaste invändning, konsekvenser och beslutskriterium | Auktoritetsnamn som ersätter argument |
| Kausal analys | Påståenden om att en åtgärd orsakar ett utfall | Orsakshypotes, confounders, kontrafaktiskt alternativ och möjlig testdesign | Att korrelation eller modellröstning räknas som kausalitet |
| Mjukvara och säkerhet | Ny skill, plugin, connector eller kodändring | Minsta diff, hotmodell, tester, beroenden, licens och återställning | Verktygssamlande och självattesterad säkerhet |

## Syntes

1. Skriv en gemensam fråga och definiera vad framgång betyder för användaren.
2. Välj högst de linser som behövs för aktuella delfrågor. Återanvänd BTF:s domänskills för
   kalkyl, byggnadsvård och UE, i stället för att låta generella specialister ersätta dem.
3. Låt specialisterna skilja observation, beräkning, antagande och förslag.
   Låt granskaren söka ett alternativ som skulle göra huvudslutsatsen fel.
4. Sammanfoga först efter kontroll av källor, mått och motstridigheter. Behåll oenighet som
   osäkerhet tills data avgör; rösta inte fram sanning.
5. Ge ett konkret beslut eller experiment, kontrollpunkt och avbrytningsvillkor.
   Värdera ny research efter om den kan ändra beslutet; kr-effekt anges bara med underlag.

Exempel: en långsam offertprocess behöver sannolikt processmätning, statistik och
användarflöde, inte kvantfysik. Ett verkligt kvantalgoritmval behöver däremot
kvantkompetens och en klassisk baslinje, inte ett allmänt löfte om större intelligens.
